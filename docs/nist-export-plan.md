# Plan: ANSI/NIST-ITL export (`.an2`)

Status: phase 1 built, 2026-09-25. A person's page has **Download → NIST (.an2)**, which opens the export page
at `/biometrics/<run>/<subject>/nist`.

## 1. Goal and decisions

Export a synthetic person as ANSI/NIST-ITL transactions that an ABIS can load, mainly to **enrol** them, and
optionally with face probes to **search** for them.

Decisions made:

- **Format: what abis_next supports.** ANSI/NIST-ITL 1-2011 Update:2015, Traditional (tagged binary) encoding,
  version `0502`. The current INTERPOL implementation (INT-I v6.00.01, 2020) is **XML only** ("the legacy
  tagged record format is no longer supported") and requires WSQ or JPEG 2000 for prints; that is phase 3.
- **A separate page**, not the download menu, with three choices:
  - enrolment content: prints and face, prints only, or face only
  - search: any of the subject's face probes, each as its own transaction (the aged and changed-appearance
    images first)
  - compression for prints and palms: PNG or WSQ
- **Codec copied from abis_next, not shared.** `Phantom.Nist.Record`, `File`, `Field` and `Type1` come from
  abis_next commit 8ee0b48 (`lib/abis_next/nist/`); `Type14` is its builder with parameters; `Type10` and
  `Type15` are new. A shared library can come if a third project needs it.

## 2. What a download holds

| File | Records | Role |
|---|---|---|
| `<code>_enrol.an2` | Type-1, Type-2, Type-10 per mugshot, Type-14 per rolled finger and slap, Type-15 per palm | Enrol |
| `<code>_search_aged.an2`, `_search_appearance`, `_search_rebooking`, `_search_uncooperative`, `_search_glasses`, `_search_low_res`, `_search_icao` | Type-1, Type-2, one Type-10 | Search, mated with the enrolment |

- The enrolment has capture 1 only. The tenprint card is left out, since its prints are already in the file.
- One transaction downloads as the `.an2`; several as `<code>_nist.zip` with the files and a README.
- IDC 0 is the Type-2, then images get IDC 1, 2, …; the Type-1 CNT lists every record.
- Records are built one at a time as the download streams, like the ZIP export.

## 3. Images

- **Prints and palms, PNG:** the stored 8-bit grey PNG goes in byte for byte, so `subject.json`'s SHA-256 still
  identifies it.
- **Prints and palms, WSQ:** decoded with `vix` (libvips) and compressed with NIST NBIS `cwsq` at 0.75 bits per
  pixel, which NBIS documents as 15:1 (a real rolled print went from 600 KB raw to about 29 KB, about 21:1,
  since its white background compresses well). `python_biometrics/setup.sh` now also builds `cwsq`, `dwsq` and
  `an2ktool`; `NBIS_BIN` overrides the location. Without `cwsq` the WSQ option is disabled.
- **Faces:** the face model stores RGBA PNG, and Type-10 has no colour space with alpha, so faces with alpha are
  flattened onto white and re-encoded as RGB PNG. Faces without alpha go in as stored.

## 5. Verification

- Unit tests for the codec (ported from abis_next) and every record builder's fields.
- Export tests decode each transaction and check CNT, IDCs, field values, the synthetic marker, the image bytes
  and the ZIP. Tests with real images check alpha flattening and WSQ.
- NBIS `an2ktool -print all` reads the enrolment and search files without errors (a test, skipped without the
  tools). It warns that version `0502` is newer than it knows, then parses every field.
- A real subject (3 faces, 10 rolled, 3 slaps, 4 palms) exported to 32 MB as PNG and 7.9 MB as WSQ. Both parse
  with `an2ktool`, and an extracted WSQ image decodes with `dwsq` to 800 × 750, 500 ppi.
- Not done yet: loading a file into abis_next. It needs `mix deps.get` there after the latest pull, and
  `dwsq` for WSQ files (`mix fingerprint.setup_nbis`). Then: `mix fingerprint.import_nist <file>.an2`.

## 6. Next

1. **Run-level export**: every subject of a run, for bulk enrolment, and a `mix biometrics.export_nist` task.
2. **Prints as search**: captures 2 and 3 of the prints as their own search transactions (mated with capture 1).
3. **INTERPOL INT-I v6**: an XML (NIEM 2.1) encoder, checked against INTERPOL's XSD with `xmllint`
   ([INTERPOL-Innovation-Centre/ANSI-NIST-XML-ITL-Implementation](https://github.com/INTERPOL-Innovation-Centre/ANSI-NIST-XML-ITL-Implementation)).
   INT-I specifics to handle: TOTs `CPS`/`NPS`/…, its Type-2 fields, at most 4 Type-10 faces, one person per file,
   WSQ at 500 ppi (so no PNG prints), and face SAP 30–52, which means mugshots that genuinely meet SAP 30 or 40
   (see [image-resolution.md](image-resolution.md)).
4. **Type-9 ground truth**: EFS minutiae from the ground truth, opt-in. Two things to fix from abis_next's
   `Type9`: it expects `"ridge_ending"` where Phantom says `"ending"` (everything would be written as type `X`),
   and Phantom's angles point about 180° from ANSI/INCITS 378, so they need converting, with a test against
   `mindtct`'s detected minutiae.
5. **Faces as JPEG** (`JPEGB`) for receivers that don't take PNG, and SAP levels with their composition rules.
6. **Slap segmentation** (14.021 SEG) and NFIQ 2 scores (14.024 FQM), which Phantom already computes.
